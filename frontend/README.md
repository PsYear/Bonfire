# Bonfire Frontend

基于 Vite、TypeScript 与 Three.js 的实时交互篝火原型。

## Vercel 部署

在当前目录使用已登录的 Vercel CLI：

```bash
vercel link --yes --project bonfire
vercel deploy --prod --yes
```

`vercel.json` 使用 `VITE_STATIC_DEPLOYMENT=true` 构建，仅发布篝火页面。
线上默认打开「调节」，保留声音、鼠标、键盘和本地摄像头手势控制；
Agent 需要独立后端，因此在线上隐藏入口并跳过接口健康检查。
`.vercelignore` 排除录制页面及其源码、独立构建产物和环境变量文件，
录制路径与未匹配路径返回 404。后续部署沿用同一配置。

## 启动

当前目录包含前端与 PRD，尚未包含 `backend` 目录。篝火渲染、鼠标和键盘控制
可以独立运行；Agent 需要 `127.0.0.1:8000` 上的 GLM 接口，手势样本存储
需要 `127.0.0.1:8001` 上的采集接口。若本机已有这些服务，可以直接启动前端。
下列后端启动命令适用于已补齐 `backend` 目录的情况。

先从仓库根目录启动 GLM 接口：

```bash
PYTHONPATH=backend python3 -m uvicorn llm_api.server:app --host 127.0.0.1 --port 8000
```

再启动前端：

```bash
cd frontend
npm install
npm run dev
```

打开 `http://127.0.0.1:5173`。

端口被其他项目占用时，可以使用独立端口：

```bash
npm run dev -- --port 5180 --strictPort
```

此时打开 `http://127.0.0.1:5180`。浏览器标签页显示 Bonfire 和本地火焰图标。

在 Agent 输入框上方右侧点击「输入 API Key」，输入智谱 API Key 后保存。
默认勾选「记住此浏览器」，刷新后自动使用；取消勾选仅在当前页面内存中使用。
同一按钮可替换或清除 Key。尚未设置 Key 时执行指令会打开设置窗口并保留输入。
后端无需 Key 即可启动，只使用每次请求的 `Authorization: Bearer`，不读取本地
密钥文件或环境变量，也不保存页面提交的 Key。浏览器缓存使用 `localStorage`
的 `bonfire.api-key`；存储被禁用时退回当前页面内存。
每条模型回复下显示接口实际返回的输入、输出 Token 数，包含该次上下文与工具指令；
接口未返回的计数字段显示「未返回」。开场提示、撤销提示及未调用模型的操作不计用量。

## 独立手势采集页

先在仓库根目录启动采集存储服务：

```bash
PYTHONPATH=backend python3 -m uvicorn gesture_capture:app --host 127.0.0.1 --port 8001
```

前端运行 `npm run dev:capture`，打开 `http://127.0.0.1:5174`。
点击「开启摄像头」申请权限，选择上挥/下挥/静止和速度幅度，每次倒数后按提示
挥动一次。视频和带标签的关键点自动保存到 `backend/recognize_data`，右侧样本库
提供回放、掌心轨迹、标签/备注修改和排除误录；刷新后仍可查看。依赖安装与数据格式见
[`recognize_data/README.md`](../backend/recognize_data/README.md)。此页无需 GLM，
与篝火页分别运行；两页使用独立 Vite 缓存，避免同时运行时依赖缓存相互覆盖。
当前已经接入 13 组用户样本拟合的参数，新增数据后可手动重新拟合。
生产构建命令为 `npm run build:capture`。

若篝火页运行在 5180，采集页可使用 5181，并指定返回篝火页的地址：

```bash
VITE_STUDIO_URL=http://127.0.0.1:5180 npm run dev:capture -- --port 5181
```

## 功能

- WebGL2 三维体积火焰、烟雾、热折射、余烬和动态火光
- 烧蚀缺口、深炭缝、破碎凹端面与灰白灰壳，炉底散落薄灰片
- 六根木柴分别采用粗长节柴、粗短炭块、扁劈柴、细弯枝、重度灰化残段和碎劈条；每次刷新随机生成新尺寸与损伤，燃烧过程中保持稳定
- 炭火红热亮度：0–100%，默认 70%，独立控制木柴与炭床的暗红余烬；保留局部忽明忽暗，0% 关闭可见红热光
- 火势、风力、环境、声音及高级参数控制
- 右侧「调节」中的风向小旗子配合 0–360° 滑块绕旗杆转动，实时同步火焰、烟雾、火星和风车；默认 90°，从正前方向场景里吹。0/360° 向右、90° 向里、180° 向左、270° 向外。鼠标拖动同步旗子与角度，Agent 自动风向也实时显示；拖动滑块即可接管，一次拖动只记一步撤销，暂停时可预设下一吹向。
- 篝火左侧的小风车随风加速、减速和晃动，扇叶、支杆和底座有随几何变化的地面投影；强风侧吹火焰、烟雾与火星，鼠标风向也联动风车
- 燃烧强度 0–400%，默认 50%；每次单击添柴增加 10 个百分点，最高 400%，可逐次撤销。持续维持设定火势，低档微火、高档强火，只有主动设为 0 才停止燃烧
- 两侧火星爆裂频率：左右独立随机向外喷溅，0% 关闭自动爆裂，与持续火星数量分别控制
- 三种场景预设和高、中、低实时画质
- 按住鼠标左键拖动控制风向、单击添柴加火、暂停、声音和沉浸模式；右上角交互说明以图标和文字展示操作方式，点击外部或按 Esc 收起
- 方向键控制：↑ / ↓ 每次增减 10 个百分点火势（0–400%）；← / → 每次转动 10° 风向，循环跨越 0/360°，并接管 Agent 自动风向。按住可连续调整，同一次按住的重复事件合并为一步撤销。参数同步滑块、数值、旗子、火焰、风车和声音；暂停时也可预设参数。输入框、选择器和滑块内保留原有方向键行为，设置窗口与交互说明打开时不修改场景。
- 摄像头手势控制：点击顶部手掌图标，允许摄像头，让整只手入镜。掌心朝上托举增加 25 个百分点，掌心朝下压动减少 25 个百分点，范围 0–400%，每次可单独撤销；自然回位后可连续操作。暂停动画或切到后台时暂停识别，关闭预览立即释放摄像头。
- 手势触发时，左下角火势百分比逐值向上或向下滚动，并短暂显示本次增减量；实际火势立即生效，撤销或手动调节会同步校正读数。沉浸模式下也会短暂显示手势反馈；系统减少动态效果设置下直接更新数值。
- 展开工作台时，篝火在剩余预览区域平滑居中并自适应取景；宽屏侧栏位于右侧，760px 及以下工作台位于下方，保留上方篝火画面。收起后回到全屏居中，暂停及沉浸控件显隐同样支持布局调整。
- 声音以真实木柴篝火的近距离噼啪录音为主，叠加少量随机脆响与点击添柴的爆裂簇；日常风力没有持续风噪，强风时只加入轻微空气声
- GLM 5.3 Flash 多轮场景 Agent
- 对话支持“帮我 1 秒往左吹，1 秒往右吹，循环”，也可说“左 2 秒右 3 秒循环”“改成每边 2 秒”“停止循环”“一直向左吹”
- 对话支持绿色、紫色、蓝色等任意火焰颜色，Agent 选取十六进制 `flameColor` 并同步修改体积火焰和周围火光；“更多调节”支持选色、输入色值与恢复预设。调色盘通过 `input` 事件实时预览，连续选色只记一步撤销，暂停时也立即更新。
- 结构化 `update_fire_scene` 工具调用、参数校验和撤销

生产构建：

```bash
npm run build
```

## 实时渲染方案

火焰使用 GPU 上的三维场模拟与体积积分，替换原来的透明球体叠加。

- `src/volumeFire.ts`：64×80×56 体素以二维切片图集保存，半浮点双缓冲维护世界坐标速度、温度、燃料、烟尘和燃烧反应。固定 30 Hz 时间步沿 X/Y/Z 回溯平流，执行温度浮力、实际速度场的涡量增强、压力投影、燃料反应与冷却。持续演化的三维旋度噪声直接推动热气内部的侧向卷曲与回旋，热解气体也沿表面法线及局部切向逸出；各处涡流相位不同，镜头仍保持固定。
- `src/fireIntensity.ts`：燃烧强度统一使用 0–400% 的实际火势，默认 50%；去除此前 120% 的内部上限。单击添柴通过共用配置每次增加 10 个百分点，不再叠加随后衰减的临时火势，保留火星与声音反馈。温暖/余烬/旺火预设分别为 120/15/300%，Agent、数值校验、重置与撤销支持完整范围。滑杆填充按自身最大值归一化，音频映射仍落在原有 0–1 范围。
- `flameColor` 默认为 `null`，使用原有 `flameTone` 黑体色调；自定义颜色使用标准 sRGB 十六进制，接受 `#RRGGBB` / `#RGB` 并统一为大写六位色值，非法值不应用。自定义色在 Three.js 中转换为线性颜色后驱动火焰发光，保留温度和反应层的亮暗变化；光源定位读取同一发光函数，点光源和反射补光同步使用该颜色。单独改色不改变火势、气体运动或定时吹风，暂停时也能改色。切换自然色调、预设或重置清除自定义色，撤销可恢复先前颜色。
- `src/fireWind.ts` / `src/windmill.ts`：风力以非线性曲线映射到地面参考流速，连续阵风改变大小。鼠标风向只在场景内按住左键拖动时更新，取拖动的相对位移，与所在屏幕区域无关：向右拖向右吹，向左拖向左吹；上拖加入场景里（-Z）、下拖加入场景外（+Z）的分量，纵深灵敏度为横向的 0.65 倍。累计位移达到 3 像素才更新风向，过滤抖动并支持慢速拖动；松开后保留上一吹向。指针捕获保证移出场景后仍能结束手势，松开、失焦、暂停或切换控制后重置移动基线，重新按下才开始控制。单击在松开时触发增强和爆裂音，拖动不触发点击增强。过渡保留气流惯性，0% 停风，鼠标不会额外产生风。同一个 X/Z 风向量驱动三维气体和小风车，火星采样实际气流；机头的扇叶正面朝向来风，尾翼位于下风侧，转向时平滑跟随。转子按相对机头的受风旋转，保留惯性和停风滑行，停风不重置机头方向。支杆用带子步长的阻尼弹簧响应阵风。木柴附近侧风作用较弱，上部火舌受到更强的剪切和热涡牵引，形成侧弯与局部摆动；垂直方向保留浮力，反向风使用正阻尼。风车为风力的可视化示意。
- Agent 通过 `windMode`（`manual`/`fixed`/`alternating`）、`windDirection`（固定吹向或循环首方向）、`windLeftSeconds`/`windRightSeconds`（0.1–60 秒）控制风向。定时模式按真实活动时间切换，暂停和后台期间冻结；改变节奏或首方向从新周期开始，调风力、颜色等保留周期进度。自动风向直接驱动共用风输入，气体和风车保留各自惯性，鼠标不会抢占自动模式。重置、预设恢复鼠标风向，撤销可恢复循环配置。循环不改变已有非零风力；停风状态下要求开始循环时 Agent 将风力设为 40%。停止循环恢复原有鼠标/输入映射，固定风向也可通过对话指定。
- `windAngle`（0–360，默认 90）对应 X/Z 地面上的单位向量 `[cos(angle), 0, -sin(angle)]`，默认指向场景里（-Z）。滑块或 Agent 指定角度时使用 `manual` 模式。手动拖动场景会写回同一角度，切换输入映射不会重置为右风。旗子用 CSS 3D 绕固定竖杆旋转，自动模式只读取共用风输入，不改变循环进度；手动滑块接管与角度变化一起撤销。重置和三个预设恢复 90°。
- 风对火焰的作用在气体求解中增强：中档风力提高横向耦合，上部剪切和热气的下风侧牵引形成明显侧弯、拉伸；高度错相的阵风与局部热涡产生摆动。木柴附近按表面距离减弱受风，燃料源保持原位；0% 时附加风作用归零，气体自然回正。风力输入仍与风向旗子、风车共用，火星采样增强后的实际气流；保留原有速度/加速度上限与模拟分辨率。
- 压力求解与速度导数使用各轴的实际体素尺寸；木柴边界采用近似无穿透条件。热区允许局部气体膨胀，不同反应气团的膨胀率独立起伏。每个体素保存最近木柴的表面坐标，只有该位置正在热解的木质才向气体释放燃料及显热，再在混入空气后发生简化反应。
- 强度提高时，燃料释放率和供氧参与度一并提高，持续补给维护可燃库存。气体运动近似卷入空气，富燃料区域继续在混合时反应；高档提高浮力、侧向卷曲和热气保温，并增强体积吸收与辐射。速度保持有限上限，体素场、固定镜头和积分步数不变，域顶部渐隐以避免截断火舌。
- 同一模块按不透明场景深度限制 Ray Marching，使用吸收与透射率合成薄燃烧反应层和烟雾。高/中/低画质分别使用 112/72/48 个视线采样；压力求解分别为 14/10/6 次 Jacobi 迭代。亚体素细节由三维速度输运，固定镜头将体积投影至屏幕。
- `src/woodFracture.ts`：参考[林火后炭化木材实拍](https://everytexture.com/everytexture-com-stock-wood-texture-00044/)，生成各木柴独立的顺纹长沟、错位横裂与局部分叉。开口宽度、深度、走向和长度独立变化，横裂局部中断；端面也有不等间距的径向破裂。同一断裂场驱动几何凹陷、凹凸贴图、沟底遮蔽和零散余烬，避免完整炭块轮廓同步发亮。
- `src/woodVariation.ts`：一次加载使用一个随机种子，六类木柴的长度、粗细、椭圆/劈开截面、弯曲、锥度、烧蚀腰部、两端破损、沟壑数量与宽深、灰化范围和细表面材质分别变化。整体长短粗细差异由不同形态的取值范围保证；刷新会生成新的一组，热模型与碰撞场在本次燃烧过程中共用稳定参数。
- `src/woodShape.ts` / `src/firePhysics.ts`：可见木柴和碰撞体共用位置、旋转、尺寸，以及预计算的 128×96 烧蚀轮廓。深纵缝、错位横裂、局部缺块、残缺端缘与内凹端面同时进入网格和近似符号距离场，供气体绕流、暴露燃烧表面筛选与火星碰撞使用；细小纹理凹凸不进入碰撞体。
- 弯曲的局部中心线同时用于网格、碰撞法线、燃烧表面坐标、热气探针与火星源；改变形状后燃料和红热仍对应同一块木材表面。
- `src/woodCombustion.ts`：六根木柴各有 48×48 个表面单元，以 15 Hz 计算局部导热、热气反馈、炭床传热、热解吸热、炭燃烧放热和冷却。各木柴孔隙区域以不同速度和相位连续变化，局部热解时强时弱，释放率驱动同一表面上的 GPU 燃料源。持续补给补回反应消耗的木质与炭，保留初始可燃库存、炭化和灰壳分布；炭床维持与当前火势对应的温度，已受热表面也获得维持加热，避免燃料耗尽或冷却反馈让火焰随观看时间自然熄灭。灰化位置的可燃库存更少，仍抑制燃料释放和发光。主动设为 0 后停止燃料与维持加热，现有热气消散、余温逐渐衰减。该模式面向持续观看，不模拟库存自然燃尽。
- `src/fireMaterials.ts`：各木柴与端面使用独立的程序化木纹、断裂、粗糙度、凹凸与环境遮蔽贴图。烧蚀网格形成缺块与有沟壁的深裂缝，灰白颗粒状外壳集中在凸起表层，沟底保持深黑与局部红热，炉底有积落的薄灰片。保留初始炭化与灰壳状态，局部温度决定红热范围和亮度，灰层抑制发光。各个小区域独立缓慢闪动，暂停时冻结热状态、闪动与风车运动。破损形状与积灰是程序化初始状态，未求解动态折断、灰片脱落或木柴塌落。
- `charGlowIntensity`（0–100，默认 70）在“调节 → 核心参数”中控制木柴与炭床的红热显示亮度。50% 对应此前强度，70% 约为此前的 1.96 倍，100% 为 4 倍；0% 关闭红热显示。参数只缩放余烬材质发光，局部温度、灰壳遮挡及闪动仍决定发光位置；暂停时也可调亮度。温暖/余烬/旺火预设分别为 70/85/65，Agent、参数校验、重置与撤销均支持该参数。
- `src/fireSparks.ts`：批量实例化细小轨迹，按真实热解热点的权重选择暴露木柴表面，冷木质不产生火星。气体速度与温度以 10 Hz 从 GPU 降采样至 16×24×16 缓存；速度经三线性插值驱动火星的质量、阻力、重力与冷却，温度经同样插值反馈木柴。数量同时受局部燃料释放率、火势及火星参数控制，熄火后停止生成。
- `sparkBurstFrequency`（0–100，默认 35）控制自动爆裂的事件频率。左右独立使用随机事件时钟，一次爆裂从该侧正在热解的木柴位置喷出一簇碎屑，带有向外的初速度和不同质量，随后受气流、阻力、重力及冷却影响。`emberRate` 控制持续火星；自动爆裂设为 0 后仍可保留持续火星及手动点击增强。预设、Agent、参数校验、重置与撤销均支持新参数。
- `src/fireScene.ts`：主火光使用篝火内的点光源投影。GPU 采样与画面共用的火焰发光函数，从明亮火舌的发光加权光心附近选取真实发光样本，并平滑跟随；上部火舌消失时退回实际低处火焰，取消人为增加高度。风车阴影由篝火到风车的射线投向地面，向远离火光的一侧延伸；低于尾翼的火光不会把整片尾翼投到地面。环境轮廓光只补亮，不生成固定方向的主阴影。扇叶、尾翼双面参与投影，细杆保留较小阴影偏移，底座贴地。主火光阴影贴图高/中/低分别为 1536/1024/768，画质切换时回收并重建贴图。配合局部火光、近似反射补光、线性 HDR 合成、克制 Bloom 与 ACES 色调映射。镜头按面板可见状态调整构图，避免遮住篝火。

画质档位分别限制像素比为 1.5/1.25/1，不超过设备像素比。需要支持浮点渲染目标的 WebGL2；后台标签页停止渲染，重新显示时继续。

这是物理启发式的实时近似，有限压力迭代、体素分辨率和程序化材质仍有画质边界；不等同于 Blender Cycles / Houdini 的影视离线成片，也未通过实拍盲评。

`#scene-host` 的 `data-fluid-statistics` 提供 GPU 采样热区的三轴速度 RMS、平均有向速度、热区质心、向下/向外速度样本占比、侧向动能比例和空间范围。`data-windmill` 提供实际风输入、转速（弧度/秒）、累计转数、摆角和机头方向，供风力联动验证。`data-spark-bursts` 提供左右爆裂的累计事件数及平均横向初速度。`data-wood-statistics` 提供温度、炭化/灰化、红热表面比例、平均热解率及累计归一化燃料通过量 `fuelConsumed`；持续补给模式下 `virginFuelRemaining` 保持 1、`solidMassLost` 保持 0。这些是实时模型的诊断量，不代表整根木柴实测质量或精确 CFD 误差评估。

`data-wind` 提供风力、当前与目标吹向和实际有向流速；`data-fluid-statistics.plumeLeanDegrees`
是热区在 0.65 米以上按温度平方加权拟合的横向倾斜角，左负右正，用于对比不同风档的形态响应。
它是热羽流的诊断近似，不是可见火焰轮廓的实测倾角。
`data-wind` 每帧额外提供模式、活动计时、首方向和左右时长，可测量定时切换，避免一秒一次诊断采样与一秒风向周期混叠。`directionVector` / `targetVector` / `flowVector` 提供 X/Y/Z 方向及流速，`pointerMovement` 提供最后一次有效滑动位移；原有标量方向与流速保留为 X 分量。Agent 固定与左右循环风使用纯 X 风向。

`data-windmill` 的 `facingDirection`、`headPosition` 是实际世界坐标下的机头轴与位置；
`data-windmill-shadow` 提供篝火点光源位置、机头和尾翼投向地面的几何交点，以及尾翼与其地面投影的屏幕坐标。
`data-fluid-statistics.lightCentroid` 是明亮火焰的发光加权中心；`fireLightPosition` 是靠近它的实际发光样本，
`fireLightEmission` 为该样本的发光权重。存在足够明亮的上部火舌时优先取其光心，矮火退回低处火焰；
这仍是单点光源的近似，不是完整辐射传输解。
预览地址加 `?shadow-debug=1` 时，`data-windmill-shadow.tailDepth` 额外提供尾翼内部射线的几何遮挡距离、
实际 GPU 阴影贴图距离、像素采样误差及地面距离，核对真正渲染的尾翼阴影；普通预览不执行这项深度读取。

## 篝火声音

`src/audio.ts` 使用 Web Audio 播放本地录音，首次点击声音按钮后才下载和解码，
不阻塞首屏。主录音做了低频抑制、瞬态增强与循环边界交叉淡化；低音量错位层和
随机短促木柴脆响减少机械重复感。声音资源来自 FunWithSound 的 CC0 篝火实录，
来源与处理说明见 [audio/LICENSE.md](public/audio/LICENSE.md)。

火势控制录音音量与额外脆响密度，设为 0 时停止火声；风声独立跟随风力，仅超过
60% 后逐渐出现。风声使用快起、圆峰、慢落的阵风包络，形成“呼——呼——呼”的节奏；
每阵持续时间、间隔和强弱不同，风越强，呼啸越明显、间隔越短。宽带空气噪声的滤波中心随
每阵气流上升、下降，避免固定音色或固定频率的持续风噪。阵间明显回落，木柴噼啪声仍是主体。
音量为 0 或关闭声音会静音；关闭后清理爆裂和阵风事件并挂起音频上下文，
再次开启复用已解码的录音。暂停按钮保持原有的仅暂停动画行为。录音加载失败时
使用随机爆裂声并提示。预设、重置、Agent 更新与撤销均同步声音参数。

`#scene-host` 的 `data-audio` 每秒提供开关、录音加载状态、音频上下文状态、
实际输出 RMS/峰值、音量、火势、风力与额外爆裂计数，以及阵风包络、滤波中心频率和阵风次数，供运行验证使用。

当前仍是近似的表面热模型：气体热反馈分辨率有限，反应与传热系数未做材料实验标定，氧气由混合比例及控制参数近似推导，也未求解完整木柴内部温度、完整燃烧化学或严格守恒的能量交换。

## 摄像头手势

`src/handControl.ts` 按需请求前置摄像头，只请求视频，不请求麦克风。MediaPipe
Hand Landmarker 以 320×240、最高 12 Hz 在经典 Web Worker 中运行，最多一帧正在
处理，不阻塞主线程上的三维动画。模型、运行时及 WASM 均由本站提供，摄像头画面
仅在本地处理。安装、启动和构建会从锁定的 npm 依赖复制运行时；模型已放在
`public/gesture/hand_landmarker.task`，来源见 [gesture/LICENSE.md](public/gesture/LICENSE.md)。

`src/handSwipe.ts` 的 `handSample` 共用于篝火页、采集页与离线回放。根据三维腕部、
食指/小指指根计算掌面法向，并按左右手修正方向；掌心朝上只允许上托，朝下只允许下压。
四个指尖的平均位置经三帧中值平滑，识别手腕位移很小的托举/压动，过滤追踪抖动。
最近五帧至少三帧朝向一致，140–650ms 的动作需达到按掌宽归一化的位移、速度、
纵向占比与轨迹一致性要求。触发后冷却 550ms，指尖回位、稳定停留或切换掌面朝向后
重新准备，不强制每次先静止。回收动作不触发相反方向，持续单向运动只记一次。
连续面向摄像头的手掌保留原有垂直挥动规则：稍停 220ms 后准备，触发后冷却 750ms。
丢失手部、时间间断、左右手/尺寸跳变、暂停和后台切换重置基线。
手势只更新 `burnIntensity`，与鼠标风向、Agent 循环、颜色和声音设置兼容，
使用已有参数校验与撤销历史。

个人参数位于 `public/gesture/swipe-profile.json`，只含聚合参数、样本计数、摘要哈希和
验证结果，不含摄像头视频或原始关键点。运行时静态接入，不依赖采集服务。
在仓库根目录重新拟合或复验：

```bash
python3 backend/fit_gestures.py
python3 backend/fit_gestures.py --verify
```

拟合脚本通过前端实际识别器回放，搜索 108 组参数组合，在满足识别与误触约束的组合中
优先选较保守的阈值。使用整条视频留一验证，避免把同一视频的帧拆到训练与验证两侧。
2026-11-05 的 13 组自然动作（上挥 7、下挥 6）在 12Hz、15Hz 共 26 次组合回放中
均至少识别到一个正确方向，且无反向事件；逐条留出后结果相同。
52 个由样本构造的静止、抖动、横移与慢漂移序列未触发。
Chrome 真实视频作为摄像头输入的端到端回放验证了上托加火、下压减火、数值反馈、
暂停、关闭摄像头及单步撤销，两个生产构建与原有挥动规则回归通过。

这些是整段样本的方向识别检查；部分视频有多次挥动，未逐次人工标注，
不能据此宣称每次手势准确率为 100%。尚无实际录制的静止负例；合成检查不代表
真实误触率。其他用户、光照、速度、拍摄距离与设备仍需实测。

需要 HTTPS 或 `localhost`/`127.0.0.1` 的安全上下文、摄像头权限，以及支持
Web Worker、OffscreenCanvas 和 WebAssembly 的现代浏览器。权限拒绝、无摄像头、
设备占用和资源失败均在预览内提示，支持重试；关闭、离开页面或销毁时停止视频流和
Worker。识别效果受照明、手掌遮挡和设备性能影响，建议让整只手处于画面内，
上托时掌心朝上，下压时朝下。
